Term project: PersonaSync™ Phase 3

PersonaSync is a product I founded and am building solo. The idea is simple. Anyone who uses more than one AI assistant ends up re-explaining who they are and what they're working on every time they switch, because each vendor keeps its own memory and none of it travels. PersonaSync is the piece that travels. You write down your persona and your context once, and it carries that into whatever AI tool you open.

Phases 1 and 2 are live at app.personasync.dev: the persona web app, a scoring engine that reports how complete and consistent a context is, and a set of MCP read tools so other software can read that context in a structured way. The rule the whole product runs on is that the user writes and confirms everything the system knows about them. Anything an AI suggests is tagged and stays out until the user approves it.

For CIS 641 I am building Phase 3, the delivery client. It detects which AI tool is in front of the user, offers the persona they usually use with that tool, formats the context to fit that tool's limits, inserts it, and logs what was shared with which tool so the user can review or revoke it. That is the part of the product that turns stored context into something you actually use.

The course deliverables are the analysis and design behind that client: a system request, use case and activity diagrams, CRC cards and a class diagram, sequence and state machine diagrams, and a Software Requirements Specification with traceability and a change management plan. I'm treating the SRS as the product spec, not just the course paper, so the work this semester is the design document the Phase 3 build is written against.
